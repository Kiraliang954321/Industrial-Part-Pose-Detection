## 推荐用途与两条路线

建议第一版采用分度式检测：**来料到位 → 停带/稳定 → 多帧朝向判定 → 合格放行、方向不合格分拣、无法判断停机复核**。现有 M4 静止抓取可用于分拣；无需先解决运动目标拦截。

另一条路线是不停带输送，增加运动跟踪、速度估计、延迟补偿和动态抓取。这需要新的运动数据与控制验证，不能继承静止 M4 的 24/24 成绩。

不把模型无法判断的零件用真值坐标自动抓入复核区。缺少可靠抓取观测时，安全状态是停止工位并保留该件，后续恢复须显式记录。

## 语义与边界

- 对象继续使用 `screw_proxy_v0`；具体工业件型号和真实公差仍未知。
- 第一版只判断冻结参考方向下的头尾/有向轴线，不捏造正反面或质量缺陷。
- 系统事件为 `PASS / FAIL_ORIENTATION / UNCERTAIN`；GT 为 `CONFORMING / NONCONFORMING / INDETERMINATE`，两者分开。无法预测不等于 GT 为 INDETERMINATE。
- 合格角度与一致性阈值仅作为仿真开发 Recipe，不能填作真实 Operating Envelope。开发/校准与后续评价来源隔离。
- 多帧统计使用 360° 有向角；头尾相反不能通过模 180° 聚合消失。缺失、不一致或不可用的证据会拒绝，不只平均成功帧。
- 分度式单件工位可依赖模拟光电到位信号/工位状态建立事件；这些信号必须明确声明。不能把仿真对象 ID 或真值位姿当作视觉跟踪结果。
- 如使用故障注入，记录其来源与影响，例如相机无图/遮挡；不直接强制一个想要的决策来制造演示。
- 分度输送与静止抓取验证不代表不停带动态抓取。仿真时间、运行墙钟和实际工位吞吐分开，不声称已实现真实流水线验收。
- M4 冻结代码/协议保持可复现；流水线扩展使用独立版本与运行记录，不改写 M4 已得结果。

## 已确定的首轮实现约束

用户选择“按分度式流程推进”。本轮采用独立单件索引托盘 episode：实际滑轨执行器通过接触输送零件，到位后观察 8 帧；PASS 驱动托盘到下游交接位，FAIL_ORIENTATION 由 Panda 抓到旁侧拒收位，UNCERTAIN 锁定工位。暂不实现托盘循环回程后的卸料、连续多件队列或自动复核恢复，不把 episode 重置剪辑成无间断生产线。

开发 Recipe 起点：世界 +X 为目标、合格角差 ≤10°；系统采用 2° 边界保护带、最少 5 个有效帧、有效比例 ≥75%、有向角最大离散 ≤5°、中心离散 ≤2 mm。所有数值是代理仿真开发设定。GT 在统一观察窗口结束时独立读取；单帧与多帧比较共享同一帧序列和该 GT。

首轮包含正常合格、明显偏向、头尾反向、前两帧相机掉帧、整个窗口无图、阈值边界六类情景。故障只作用于输入图像并记录，不直接指定系统决策。控制开发与后续评价种子隔离，保留每个帧的证据、唯一最终事件和实际执行结果。

## 实际实现与材料流

1. 索引托盘在滑轨执行器驱动下移动，螺丝通过接触随托盘从上料位到检测位；没有在输送阶段逐帧设置螺丝位姿。
2. 模拟 PLC 的上料 job ID 与索引编码器到位信号建立一次观察事件。这是声明的单件工位来源，不是视觉跟踪器输出，也没有实现真实 PLC/光电硬件接入。
3. 停稳后采集 8 帧，帧间隔 0.1 仿真秒。RGB 经冻结的 M3 Pose 模型与固定标定得到世界有向角和中心；事件模块不接收 GT。
4. PASS 将托盘送到下游交接位置；FAIL_ORIENTATION 使用事件聚合的预测观测驱动 Panda 抓到旁侧拒收台；UNCERTAIN 保持检测位，不调用机械臂，也不自动清除停机状态。
5. 动作结束后，独立仿真评价器核对实际位置/接触/落稳，并给执行结果和终态标签。终态的物理验收目前是仿真评分标注，不代表已实现真实抓取/到位传感反馈。GT 不参与感知判定、抓取目标计算或机械动作选择。

Panda 在拒收台统一摆放头尾方向；**入站 GT 仍取观察窗口结束时的姿态，不按分拣后的姿态改写**。M4 模型、控制代码与冻结协议保持原样，L1 使用独立适配层和新场景。

代码分工：`line/events.py` 管理帧证据与一次性判定；`line/state.py` 管理工位顺序；`line/perception.py` 只转换像素/预测；`line/control.py` 复用 Panda 并以托盘编码器补充预检；`line/metrics.py` 独立计算 GT 分母；`simulation/indexed_scene.py` 实现物理托盘/支撑面；`line/runner.py` 编排与记录。

## 定位托盘与校准记录

首轮普通接触设置出现螺丝滚落，随后改为明确记录的定位托盘；拒收台的一件螺丝也曾因滚动未满足落稳条件，被记为执行失败。最终采用有限滚动摩擦的衬垫代理接触，保留原落稳阈值，没有增加对象吸附/weld 或用位姿重置代替搬运。

| 项目 | 冻结开发值 |
| --- | --- |
| 托盘 | 170×160×12 mm，质量 0.8 kg，顶面世界 z=0 |
| 位置 | 上料 y=-0.18 m；检测 y=0；下游交接 y=+0.18 m |
| 滑轨 | 单轴位置执行器，kp 3000、kv 100、力限 ±100 N；运动速度上限设定 0.06 m/s |
| 托盘接触 | condim=6，摩擦 `1.0 0.005 0.001` |
| 拒收台接触 | condim=6，摩擦 `0.8 0.01 0.001` |
| 判定 | 目标世界 +X；GT 容差 10°；系统保护带 2°，≤8° 才 PASS，≥12° 才 FAIL_ORIENTATION，中间 UNCERTAIN |
| 窗口 | 8 帧；最少 5 帧且有效比例 ≥75%，因此当前配置实际上至少需要 6/8 有效帧 |
| 一致性 | 有向角最大离散 5°，中心最大离散 2 mm；缺失帧保留在预期窗口分母里 |

这些是代理开发设置，不是实测材料参数或真实工艺规范。定位托盘不等于普通无限循环皮带。校准使用 seeds `11000–11005`，迭代目录 `20261031-l1-calibration-v1` 至 `v4` 均保留；选用 v4 证据，4 个自动动作全部完成，2 个停机事件全部保持安全。另修复了 0.7 秒截止点的浮点比较问题，并补齐 GT 枚举检查，禁止把 UNCERTAIN 当成 GT。

## 冻结评价与结果

依据[冻结 L1 开发协议](../../data/screw_line_protocol_v1.json)，在源码、Recipe、物理设置、资产和权重不变的情况下运行新 seeds `21000–21023`。六类情景与四类有限光照/背景组合形成 24 个独立事件；每个情景 4 件，和校准来源隔离。没有在这些结果上调参。

GT 为 CONFORMING 16 件、NONCONFORMING 8 件、INDETERMINATE 0 件。故障和边界情景被有意大量纳入，这个分布不代表生产频率。单帧对照复用同一窗口首帧和统一窗口结束时的 GT，**只比较判定，不另外执行单帧动作流程**。

| 事件指标 | 单帧对照 | 多帧工位 |
| --- | --- | --- |
| PASS / FAIL_ORIENTATION / UNCERTAIN | 4 / 8 / 12 | 8 / 8 / 8 |
| 明确决策 Coverage | 12/24，50%；Wilson 95% CI 31.43%–68.57% | 16/24，66.67%；CI 46.71%–82.03% |
| Wrong Accept | 0/8；95% 上界 32.44% | 0/8；95% 上界 32.44% |
| Wrong Reject（CONFORMING 未 PASS） | 12/16，75%；CI 50.50%–89.82% | 8/16，50%；CI 28.00%–72.00% |
| 其中明确失败误拒 | 0/16 | 0/16 |
| 其中 UNCERTAIN 拒绝 | 12/16 | 8/16 |

| 情景 | 件数 | 多帧结果与含义 |
| --- | --- | --- |
| 正常合格 | 4 | 4 PASS，送至下游 |
| 明显偏向（约 90°） | 4 | 4 FAIL_ORIENTATION，Panda 分拣 |
| 头尾反向（约 180°） | 4 | 4 FAIL_ORIENTATION，Panda 分拣 |

| 整窗无图 | 4 | 4 UNCERTAIN，停机留件 |
| 合格侧边界（约 9°） | 4 | 4 UNCERTAIN，保护带拒绝；仍计入 CONFORMING 的误拒分母 |

本轮作用是证明多帧事件能够恢复短暂缺图，并让无法判断的对象留在检测位。没有因此宣称真实误放风险已得到统计保证，也没有完成边界两侧和所有生产干扰的覆盖。

实际多帧流程：唯一最终事件 24，缺失事件 0，重复事件 0；自动动作 16/16 完成（Wilson 95% CI 80.64%–100%），停机留件 8/8 符合仿真检查（CI 67.56%–100%）。无非法接触步骤，最大数值软接触穿透约 0.298 mm，最大单步对象位移约 0.350 mm；不是“零接触穿透”声明。

观察窗为 0.7 **仿真秒**。单帧的 0 仿真秒仅表示不额外等待后续帧，不是零推理耗时。多帧整段墙钟时间 Median/P95 为 1288.87/1460.61 ms，包含仿真步进、渲染、推理和证据落盘，不是实机端到端延迟。自动动作段的仿真时长 Median/P95 为 15.959/23.919 秒（n=16），未包含完整上/卸料和回程；**连续产线吞吐字段明确为 null**。
