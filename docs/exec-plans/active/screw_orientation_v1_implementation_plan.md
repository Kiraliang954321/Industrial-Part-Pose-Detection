# 螺丝朝向 V1：首轮开发与训练实施方案

日期：2026-10-31。状态：**M0–M3 视觉开发与训练、后续 M4 Panda 仿真闭环均已完成；真实门禁仍 CLOSED，M5 按暂无实物/CAD 的选择保留待办。**

用户已确认首轮研究螺丝“头尾 + 有方向轴线”。选型依据见[技术调研](../../design-docs/screw_orientation_research_20261031.md)，总路线见[工业件 S0–S4 计划](industrial_orientation_3d_execution_plan.md)。本文 M0–M5 是具体工作包，不替代既有 V4.1 Phase 门禁。

实际实现、运行目录与检查结果见[开发记录](screw_orientation_v1_development.md)；原方案中的预算起点与实际执行参数分开记录。

## 1. 已批准的第一批范围

第一批为 M0–M3：**单螺丝、固定 RGB 相机、受约束支撑场景、MuJoCo 数据生成、Traditional CV 对照、YOLO26n-Pose 开发训练及预测回放**。

尚未取得具体实物/CAD 时，建议使用自建参数化 `screw_proxy_v0` 验证软件链路。其尺寸、材质、头部与螺纹简化必须写入配置和产物，不将代理指定为真实 Part A，也不宣称真实识别率。用户若已有型号/CAD，则优先按该输入修订资产定义。

M4 为预测驱动的虚拟机械臂抓取/摆正，M5 为实拍迁移及有条件的 6D 扩展。第一批不依赖先完成机器人建模；数据生成不必让机械臂出现在每张图里。

## 2. 任务与数据契约草案

| 字段/约定 | 建议定义 |
| --- | --- |
| 任务 | `screw_directed_axis_v1`；仿真开发域，区别于旧面类任务 |
| 类别 | 单对象类 `screw`，不使用 `screw_front/back` 代替头尾 |
| 关键点顺序 | `head_axis_end`、`tip_axis_end`；具体 3D 锚点随资产冻结并附示意图，不能把任意外接框端点当成真值 |
| 输出 | 目标框、两个语义点、点置信度、朝向有效性/拒绝原因、`heading_deg`；缺失方向为 null |
| 角度 | 尾 → 头；`atan2(y_head-y_tip, x_head-x_tip)` 转角度并归一化到 `[0,360)`；图像 x 右/y 下 |
| 角度误差 | `abs(((pred - gt + 180) % 360) - 180)`；范围 `[0,180]`，头尾颠倒保留为约 180° |
| GT | 关键点坐标、已知性与可见性独立记录；投影退化/端视、遮挡分层；工位 `CONFORMING/NONCONFORMING/INDETERMINATE` 另按真实协议定义 |
| 相机 | 保存 K、分辨率、畸变约定、外参；`T_A_B` 表示将 B 坐标变换到 A；CV 相机 x 右/y 下/z 前 |
| 三维单位 | 米、弧度；旋转优先存矩阵，四元数若使用须写明顺序；渲染器坐标转换在边界完成 |
| 来源 | `asset_id/version/hash/license`、`domain`、场景/episode/source family、配置、seed、图像哈希、split |
| YOLO 导出 | `kpt_shape: [2,3]`；反射增强不交换头尾语义，映射 `[0,1]`；导出可见性映射需与安装版核对 |
| 拒绝 | 低点置信度、过短投影、退化几何等阈值仅在 Val 校准；不以拒绝删掉困难样本 |

这里的关键点契约是新增版本，不能直接向现有 `Detection`、面类 `LabelContract` 或 180° `angle` 写入新含义。两个关键点不输出完整 6D；绕轴角未定义时保持缺失。

GT 锚点可能位于遮挡表面或几何内部，须区分“投影位置已知”与“图像可见”。真实标注协议要给出可复现的落点规则与双人/二次复核方式；在该协议建立前，不把合成锚点可精确计算当作实拍也可精确标注的证据。

## 3. 数据与训练分层

| 层级 | 允许的工作 | 进入条件 | 当前状态 |
| --- | --- | --- | --- |
| 软件烟测 | 少量渲染、标签复核、短训练、预测回放 | 方案确认、资产/契约可追溯、无训练数据错误 | 已完成 |
| 仿真域开发训练 | Train/Val 拟合与选模，明确标记 `simulation_development` | 标签 QA、来源隔离、配置快照与资源预算通过 | 已完成 30 epochs；见开发记录 |
| 冻结仿真实验 | 比较方法并一次性报告未见 Test/Final Holdout | 仿真协议、split、方法/阈值、计时和统计口径先冻结 | CLOSED |
| 真实正式训练/验收 | 项目真实工况模型与指标 | 适用协议 FROZEN + Dataset Gate OPEN；具体型号与物理证据到位 | CLOSED |

前三层不打开第四层，也不替代既有真实门禁。软件烟测不冠以“正式训练完成”。

生成前按 source family / scene / episode 分组。暂定开发预算为 Train 2000 张、Val 400 张，均为独立场景快照；这是算力起点，不是满足统计显著性或正式门禁的样本量。最终 Test/Final Holdout 的场景规模与工况在仿真协议冻结时确定；不在初次选模时查看它们的预测表现。

同 CAD 用于训练与测试属于“已知对象、未见场景”；只有另行冻结并留出几何资产，才评价“未见几何”。生成配置中单独留出照明/背景等工况，报告同分布与工况迁移结果。背景、尺寸或颜色不能与头尾标签绑定。增强只作用于 Train，派生图不新增独立样本数。

## 4. 工作包与交付

| 包 | 实施内容 | 可检查交付与退出条件 |
| --- | --- | --- |
| M0：定义与环境 | 冻结本次仿真资产、锚点、坐标、schema；安装候选 MuJoCo 并验证本机渲染；保存依赖快照 | 资产 manifest、环境报告、原图/标签覆盖图；投影与坐标正确，安装不破坏既有 Torch |
| M1：数据生成与审计 | 参数化代理/已确认 CAD、固定相机、背景/光照/方位随机化；按场景分组导出关键点数据 | 可重现生成命令、数据 manifest、split plan、标签/泄漏审计、可视抽查；错误不可静默裁剪 |
| M2：两条感知基线 | 同 RGB/ROI 的轮廓与头部形状基线；自定义两点 YOLO26n-Pose 训练/推理入口 | 原始预测、统一有向角输出、拒绝原因；Traditional CV 不接收 GT mask，学习路径不含旧黄色过滤 |
| M3：开发训练与评估 | 先短训练排查数据；再单个 nano 模型开发训练；Val 选模型/阈值；冻结后才进入独立仿真实验 | 权重、配置/初始权重哈希、epoch/耗时/显存、Val 报告、失败案例和回放；不得预填准确率 |
| M4：虚拟机械臂 | 固定版本 Panda 候选、夹爪适配、运动学/路径/碰撞检查；先 GT 参考，再预测驱动组 | 相同场景配对结果、成功/掉落/碰撞/不可达及拒绝计数；无隐藏吸附或直接修改零件姿态 |
| M5：实拍迁移与 6D 条件评估 | 真实型号/尺度/标定、独立 session 采集；审计后微调与保留集评估；评估可观察自由度 | 仿真/真实分层结果；若 CAD/标定/真值/特征不足，维持有向轴任务，不虚报 6D |

M3 中冻结仿真实验的精度阈值/拒绝工作点由先行协议明确；第一批交付标准是链路可复现、计数完整且诚实报告失败，不承诺达到某个未经依据设定的工业精度。

## 6. 资源预算与依赖策略

- 已有 Python 3.11.9 / Torch 2.11.0+cu128 / Ultralytics 8.4.171 不主动升级。新增候选是 MuJoCo 3.17.0 及其必要依赖，用安装预检确认兼容，再记录实际版本与哈希。若解析要求改变核心训练依赖，改用隔离仿真环境。
- 引入 MuJoCo 的理由是新增仿真能力；兼容风险主要是 Windows 渲染后端及依赖解析，需本机验证。纯 Python 训练代码不需要项目整体重建，但使用仿真功能的环境需要安装该 extra。
- 初始权重候选 `yolo26n-pose.pt` 从官方来源获取并校验记录。若不可得，应明确报告并选择从本地模型配置初始化的替代实验，不静默换模型；旧瓶盖 OBB 权重不作为螺丝 Pose 权重。
- 烟测建议：少量生成样本、最多 2 epochs；开发训练建议起点 `imgsz=640`、`batch=4`、`workers=0`、最多 30 epochs。OOM 时降低 batch 并记录实际设置。正式比较前冻结参数；这些数值不是性能承诺。
- 第一轮开发训练预算上限建议 60 分钟，达到预算保存已有产物与状态；先记录数据生成速度，再决定后续规模。产物软上限建议 10 GiB，达到时停止生成并报告，不自动清理旧文件。
- 不预估“几分钟能完成”或“能达到多少 FPS”；记录实际预处理、推理、后处理与端到端耗时，GPU 计时执行同步。

## 7. 评价与验证办法

实施阶段做差异检查、相关模块编译/导入、现有聚焦检查及最小运行烟测；按项目默认测试政策，不在本计划中额外生成测试套件。研究数据与模型评价是本任务本身，不等同于新增软件单元测试。

必须覆盖的检查：

- 语义：0/90/180/270° 与边界角；头尾互换产生 180° 错误；缩放/裁剪/镜像后语义一致；缺失/非有限/重合关键点拒绝；方向不可用时输出 null。
- 投影：标定与坐标转换正确，保存锚点重投影覆盖图；最终训练 RGB 无标记；不以自身渲染 GT 代替真实标定验证。
- 数据：同源帧、派生图、episode 不跨 split；图像/标签一一对应；越界/不可见/无目标样本按协议保留或显式排除并计数。
- 训练：`task=pose`、单类、两点顺序检查；只使用 Train/Val 拟合与选模；报告配置、权重/数据哈希、资源和失败状态。
- 评价：检测、关键点像素/归一化误差、360° 角误差 Median/P95、方向半平面错误（有向向量点积 < 0）、拒绝率/覆盖率与条件/episode 分层。方向半平面错误不直接称为“180° 交换率”；如果单独报告交换，先冻结交换判据。
- 分母：分别列总目标、有效 GT、成功匹配、可评分方向、拒绝、漏检与额外检测。条件角误差不能替代全体任务成功率；比例给 `x/n` 和适用置信区间。
- 后续 M4：GT 仅在评估器/参考组中；预测组用自身视觉结果及预先冻结的标定/几何先验。固定支撑面不等于每帧已知物体真值 z；超出平面/高度假设的场景单列并拒绝或另建模型。
